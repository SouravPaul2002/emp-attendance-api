# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72–74) | Readiness probe returns `{"status": "ok"}` unconditionally without checking if MongoDB is reachable. | Shut down MongoDB or pass an invalid URI; `GET /health` still returned 200 instead of 503. | Added `db.command("ping")` within a `try/except` block, raising `HTTPException(status_code=503, detail="Database unreachable")` on failure. |
| 2 | `create_employee` (lines 79–85) | Check-then-insert concurrency race condition on `emp_code`. Two concurrent requests can both pass `find_one` and insert duplicates. | Firing concurrent requests with the same `emp_code` inserts duplicate documents if no DB index exists, or causes an unhandled 500 error. | Created a unique index on `emp_code` at startup and caught PyMongo's `DuplicateKeyError` to return `HTTPException(status_code=409, detail="emp_code already exists")`. |
| 3 | `EmployeeIn` (lines 53–61) | Missing input validations: `emp_code` pattern (`^EMP\d{4,6}$`), email format, string lengths, and `shift_start != shift_end` rule. | Submitting `emp_code: "INVALID"`, an invalid email, or `shift_start == shift_end == "09:30"` returns 201 instead of 422. | Added regex pattern and length constraints in Pydantic schema and added model validation ensuring `shift_start != shift_end`. |
| 4 | `create_employee` (line 82) | `created_at` timestamp stored as local naive datetime and not serialized to epoch milliseconds in API response. | Inspected DB document and API response: `created_at` was a string/datetime instead of integer epoch milliseconds conforming to `EpochMillis`. | Stored UTC datetime in MongoDB and converted it to integer epoch milliseconds in the API response. |
| 5 | `list_employees` (line 93) | Off-by-one pagination error: `skip = page * page_size` skips the first page when `page = 1`. | Querying `GET /employees?page=1&page_size=20` returned items starting from index 20, missing items 0–19. | Changed offset calculation to `skip = (page - 1) * page_size`. |
| 6 | `list_employees` (line 94) | `total` counts the whole collection (`count_documents({})`) rather than the filtered result set. | Querying `GET /employees?department=Sales` returned `total` as total count of all employees in all departments. | Updated count query to `db.employees.count_documents(q)`. |
| 7 | `list_employees` (line 95) | Missing sorting by `emp_code` ascending as required by API contract. | Queried employees list; returned order was undefined MongoDB natural order rather than ordered by `emp_code`. | Added `.sort("emp_code", 1)` to the MongoDB query cursor. |
| 8 | `punch_in` (lines 101, 113) | Crash on unknown `emp_code`. If employee does not exist, `emp` is `None`, causing `TypeError: 'NoneType' object is not subscriptable`. | Sending a punch-in for a non-existent `emp_code` threw an internal 500 error instead of 404. | Checked `if not emp: raise HTTPException(status_code=404, detail="Employee not found")`. |
| 9 | `punch_in` (lines 104–118) | Check-then-insert race condition. Two simultaneous punch-ins for the same employee and date both pass `find_one`. | Two concurrent punch-in requests created two attendance logs for the same day. | Created a unique compound index on `("emp_code", "date")` at startup and caught `DuplicateKeyError` to return 409. |
| 10 | `punch_in` (lines 102–103) | Timestamp and R1 date calculation ignored IST timezone, whole-second truncation, and overnight shift transitions. | Punching in at 01:00 for an overnight shift (22:00–06:00) assigned the record to today's date instead of the previous day's shift date. | Converted epoch ms to UTC datetime truncated to whole seconds, computed IST calendar date, applied overnight shift logic against `shift_end`, and stored UTC datetime. |
| 11 | `PunchInIn` / `punch_in` (lines 66, 109) | Status field accepts arbitrary strings rather than strictly `PRESENT`, `WFH`, `ON_DUTY`. | Sending `status: "LEAVE"` or `"ABSENT"` at punch-in succeeded with 201 instead of 422. | Restricted status to `PresenceStatus` enum (`PRESENT`, `WFH`, `ON_DUTY`) returning 422 on invalid values. |
| 12 | `punch_in` (lines 119–120) | Internal MongoDB `_id` leaked in response as `id`. | API response contained `"id": "..."`, violating contract where attendance records have no ID. | Removed `doc["id"]` and stripped `_id` completely from response payload. |
| 13 | `compute_late_minutes` (lines 33–37) | Timezone mismatch and incorrect grace period evaluation. Uses `.replace()` without timezones and does not compute floor minutes. | Punch-in at 09:40:00 (inside 10-min grace for 09:30 shift) or overnight shift punch-ins produced inaccurate/negative values. | Truncated seconds, calculated difference between punch-in instant and shift start instant in UTC/IST, checked strict `> 600s` grace, and returned `floor(seconds / 60)`. |
| 14 | `compute_work_hours` (lines 40–41) | Python's built-in `round()` uses round-half-to-even (banker's rounding) instead of half-up rounding (R4). | Duration resulting in `2.525` rounded to `2.52` instead of `2.53`. | Implemented standard decimal half-up rounding using Python's `decimal.Decimal` with `ROUND_HALF_UP`. |
| 15 | `compute_overtime` (lines 44–47) | Missing 30-minute minimum threshold (R3), breaks across midnight for overnight shifts, and compares naive vs aware datetimes. | Punch-out 10 minutes after shift end awarded 10 minutes overtime (rule requires 0); overnight shift punch-out raised datetime comparison `TypeError`. | Calculated difference from shift end instant in IST (adjusting end date to next calendar day for overnight shifts), requiring `>= 30` minutes to count overtime. |
| 16 | `list_attendance` (lines 144–150) | Entire collection loaded into memory with `list(db.attendance_logs.find(q))` and sorted in Python. | Severe latency and memory exhaustion when querying over ~100k records; explain showed no database-level sorting or index-backed pagination. | Replaced with database-level cursor `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)`. |
| 17 | `list_attendance` (lines 127–128) | Missing validation for date range query parameters (`date_from > date_to`). | Querying `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` returned an empty list instead of 422. | Added validation checking `if date_from and date_to and date_from > date_to: raise HTTPException(status_code=422)`. |
| 18 | `PunchInRequest`, `PunchOutRequest`, `RegularizeRequest` | Timestamp fields (`punched_at`, `punch_in`, `punch_out`) accepted strings and floats due to default Pydantic type coercion. | Submitting `"1783312500000"` or `1783312500000.0` was coerced to int instead of returning 422. | Enforced strict integers using `StrictInt` and `strict=True` with `ge=100000000000` and `le=4102444800000` to reject strings, floats, and booleans with 422. |
| 19 | Date validation across endpoints (`create_employee`, `list_attendance`, `department_trend`, `explain_endpoint`) | Non-existent calendar dates (e.g. `2026-02-30`, `2026-13-45`) passed regex pattern `^\d{4}-\d{2}-\d{2}$` and caused unhandled 500 crashes during date parsing. | Submitting `joined_on: "2026-02-30"` or query `from=2026-02-30` raised `ValueError` in `date.fromisoformat` / `datetime.fromisoformat` resulting in 500 instead of 422. | Added `validate_date` helper verifying `date.fromisoformat()` and raising 422 on `ValueError`, called on `joined_on`, `date_from`, `date_to`, `from`, and `to` across all endpoints. |
| 20 | `list_attendance` and `explain_endpoint` status filter | `status` query parameter was typed as an unconstrained `Optional[str] = None`, allowing arbitrary strings without validation. | Querying `GET /attendance?status=INVALID` returned 200 with an empty list instead of rejecting invalid status with 422 per OpenAPI schema. | Changed `status` parameter type to `Optional[Literal["PRESENT", "ABSENT", "LEAVE", "WFH", "ON_DUTY"]] = None` so invalid values return 422. |

### Items Examined and Determined Not to be Defects
* **`work_hours: null` and `punch_out: null` on punch-in**: Kept as `null`. This strictly adheres to the data model specification and openapi schema for open attendance records.
